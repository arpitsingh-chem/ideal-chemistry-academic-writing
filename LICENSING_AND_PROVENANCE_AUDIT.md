# LICENSING_AND_PROVENANCE_AUDIT

Audit of copyright, licensing and third-party material in the repository at
`v2.3.0`, and the provenance structure established for `v2.4.0`.

**Nothing in this document is legal advice.** It records what exists, what is inconsistent,
and which decisions belong to the repository owner.

## 2. The licence inconsistency (the one real defect)

| Location | Statement | Reality |
|---|---|---|
| `LICENSE` | full text of CC BY 4.0; no copyright line, no author, no year | the operative licence |
| `pyproject.toml` (v2.3.0) | `license = {text = "CC BY 4.0 (content); code provided for reuse"}` | free text is not a licence identifier; "provided for reuse" grants nothing specific |
| `README.md:253` | "Content CC BY 4.0; **code MIT**" | **no MIT licence text exists anywhere in the repository** |
| `CITATION.cff` | `license: CC-BY-4.0` | consistent with `LICENSE`, inconsistent with the README |
| `README.md` "Philosophy"/"Repository map" | implies open reuse of code | CC BY 4.0 does permit reuse with attribution, so a user is not blocked — but the README's promise of MIT is not backed by any grant |

Two problems follow:

1. **Internally inconsistent.** A reader cannot tell which terms apply to code.
2. **A promise that is not made.** Claiming MIT without MIT text is not a grant of MIT; at
   best it is a misdescription, at worst it misleads downstream packagers.

### Resolution applied on this branch

* `pyproject.toml` now uses a **PEP 639 licence expression** (`license = "CC-BY-4.0"` plus
  `license-files`), which is machine-readable and matches the actual `LICENSE` file.
* The README now states the licence **as it is**, and no longer advertises MIT.
* **No relicensing was performed.** Changing a project's licence is the copyright holder's
  decision, not an automated one, so it is raised as an explicit owner decision (§6, D-1).

## 3. Copyright ownership

* `LICENSE` contains **no copyright line** — only the CC BY 4.0 text. CC BY 4.0 requires
  attribution, but there is no stated attribution party, which weakens enforceability and
  leaves users unsure whom to credit.
* Git history authorship (11 commits at audit time):

| Author identity | Commits |
|---|---|
| `Arpit Singh <arpitsingh-chem@users.noreply.github.com>` | 8 |
| `PaperForge <paperforge@users.noreply.github.com>` | 2 |
| `IISER-Bhopal-Chemistry <chemwriting@iiserb.ac.in>` | 1 |

* `CITATION.cff` names **"Arpit Singh", Department of Chemistry, IISER Bhopal**.
* The project brief names the owner as **"Arpit Rajput"**.

The two names differ. Choosing the legal name for a copyright notice is the owner's
decision; inventing or merging names is exactly what this audit must not do. The audit
therefore **adds no copyright name** and raises it as §6, D-2.

**Important:** the commit authored as `IISER-Bhopal-Chemistry <chemwriting@iiserb.ac.in>`
suggests institutional involvement in at least one commit. If that work was done in an
institutional capacity, the employer may hold rights to that contribution. This must be
resolved by the owner (D-2) before any licence change. Git history has **not** been
rewritten, and must not be.

## 5. Data licensing (what the project may redistribute)

| Dataset | Redistributable? | Basis |

| `publications-openalex.json` (1,616 works) | **Yes** | OpenAlex metadata is CC0 |
| `journals.csv`, `journal-activity.csv` | Yes | derived counts + factual journal names |

The project ships **no** paywalled text, no scraped full text, and no personal data beyond
author names that are part of the public bibliographic record.

## 8. What was deliberately **not** done

* Git history was not rewritten, amended, or squashed — legitimate institutional
  authorship is preserved.
* No third-party attribution was removed to make the project look solely authored.
* No licence was applied to third-party material.
* No copyright line was invented.
* No claim was made that a licence grants more than it does.
